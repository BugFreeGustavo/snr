## Purpose

This section documents how the SNR domain is transformed into product capabilities.

The Domain documentation defines what exists within the Professional's world.

The Architecture documentation explains how responsibilities are organised to protect that domain.

This Solution documentation defines the capabilities that SNR must provide in order to deliver value to the Professional.

It represents the bridge between domain understanding and future implementation while remaining independent of technology, frameworks and user interface design.

## Relationship with the Product Vision

The Solution documentation fulfils the product promise defined within the Product documentation.

The Product documentation establishes the following guiding principle:

> Every completed project should make the next project easier.

The Solution documentation explains how that promise is achieved.

By preserving reusable professional knowledge, recovering professional context and reducing the need to rediscover existing information, SNR transforms accumulated experience into future professional value.

---

## Why This Documentation Exists

Understanding the domain is not sufficient to build a product.

Understanding the architecture is not sufficient to deliver value.

A solution must explain what the Professional should be able to achieve through the product.

Rather than describing features or implementation, this documentation defines the capabilities that fulfil the product's promise and the reasoning behind their design.

---

## Documentation Structure

The Solution documentation is organised into three complementary perspectives.

### Capability Discoveries

Records the observations and reasoning that explain why specific capabilities exist.

These discoveries originate from understanding how Professionals work and how professional knowledge influences future decisions.

---

### Capabilities

Defines the outcomes that the Professional should be able to achieve through SNR.

Capabilities describe value independently of implementation, interface or technology.

---

### Solution Principles

Defines the principles used to evaluate future product decisions.

These principles ensure that every future capability and feature remains aligned with the purpose of SNR.

---

## Document Relationships

The documents should be read together.

Capability Discoveries explain why capabilities exist.

Capabilities define what the Professional should be able to achieve.

Solution Principles explain how future solution decisions should be evaluated.

Together, they describe how SNR transforms professional knowledge into professional value.
