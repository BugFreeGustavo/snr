## Purpose

The Application layer defines how the Professional interacts with SNR.

While the Domain defines what the Professional knows, the Architecture organises that knowledge and the Solution identifies the capabilities that deliver value, the Application describes how those capabilities are experienced through professional interactions.

The Application does not introduce new business concepts or implementation details. Instead, it ensures that every interaction supports professional decision-making by presenting the right context at the right time and preserving knowledge naturally as work is performed.

## Relationship to Previous Waves

The Application layer builds upon the work established in the previous documentation.

- **Wave 2 – Domain** defines the Professional's world.

## Relationship with the Product Vision

The Application layer fulfils the Product Promise established in Wave 1.

By presenting the right context at the right moment and preserving professional knowledge naturally, every completed Project contributes to making the next project easier.

> **Every completed project should make the next project easier.**

---

## Scope

The Application layer focuses on behaviour rather than implementation.

It describes how the Professional interacts with SNR, how context supports professional decisions and how knowledge is naturally captured during everyday work.

Implementation details, technologies and user interface design remain outside the scope of this documentation.

---

## Guiding Principle

> **Every application interaction should help the Professional make better decisions by delivering relevant context while preserving knowledge for future work.**
